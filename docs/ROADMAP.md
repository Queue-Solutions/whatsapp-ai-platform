# Platform roadmap

Implemented in development: hosted test-number messaging and recovery, bounded approved-knowledge AI, the knowledge dashboard, and a human inbox with audited pause/resume and guarded manual text replies. See `VALIDATION.md` for verified behavior and remaining real-delivery acceptance. The items below retain the broader plan; client onboarding remains future work.

1. **Hosted foundation acceptance:** apply the migration, verify the hosted API, get the Meta test number, run the real Arabic/English round trip, replay duplicates, and verify takeover suppression. Add durable worker scheduling and queue monitoring before sustained traffic.
2. **OpenAI:** implement the existing ReplyStrategy contract. Add structured output validation, model/prompt versions, timeout and spend limits, per-turn usage records and explicit escalation outcomes. Keep echo available for transport diagnostics. Choose and verify the current OpenAI API/model when implementing, not before.
3. **RAG:** use tenant-scoped published FAQs and facts first; add documents/chunks and pgvector once the embedding model and dimensions are selected. Include tenant filters in retrieval SQL, document versions, citations, stale-content handling and no-answer escalation. Facts like opening hours should remain editable structured records.
4. **Admin and inbox:** Supabase Auth, membership provisioning, tenant selection, server authorization, inbox/history, knowledge editing and audit records. Use RLS user sessions for browser reads. Add a dedicated audited takeover/resume operation; never expose the service key to the browser. A handoff cannot recall a message already sent or in flight.
5. **Lead intent and analytics:** separate asynchronous analysis jobs after persistence; keep score, reasoning, model version and timestamps. Aggregate from persisted events. Avoid labels such as “dummy client.” Keep inferred sentiment distinct from customer feedback.
6. **CSAT:** collect a real customer rating tied to a prompt and source message. Store it separately from inferred sentiment and prevent duplicate ratings. Handle WhatsApp messaging-window/template requirements for follow-ups.
7. **Client pilot:** only after the preceding milestone passes, verify supported Coexistence for the client's account and number, backups and the exact onboarding flow. Preserving old chats and Business app access is mandatory. Do not promise full dashboard history import. Add per-channel credential storage, media/privacy retention policies, audit logging, alerts and recovery procedures before live traffic.
